NAS hp1 – Operations Guide

Debian 13 · OpenZFS RAIDZ1 · Samba · Jenkins · Homelab · Last updated: June 2026

Overview

hp1 is a local homelab NAS running Debian 13 (Trixie), fully managed by the Ansible playbook nas.yml. The machine is on the local network (192.168.10.50) and is not directly reachable from the internet.

Run Playbook

Prerequisite: md RAID must be dissolved first The playbook aborts if /dev/md0 still exists. All data must be backed up and the md array manually dismantled before running. See migration notes in nas.yml.
  1. Create vars.yml from template and fill in values:
    cp inventory/host_vars/hp1/vars.yml.example inventory/host_vars/hp1/vars.yml
  2. Create and encrypt vault.yml:
    ansible-vault encrypt inventory/host_vars/hp1/vault.yml
  3. Deploy SSH key:
    ssh-copy-id -i ~/.ssh/id_ed25519.pub raphael@192.168.10.50
  4. Run the playbook:
    ansible-playbook nas.yml --ask-vault-pass

ZFS Management

# Pool status and integrity
zpool status data

# Space usage
zfs list

# Compression ratio
zfs get compressratio data/shared data/angelika

# Manual scrub
zpool scrub data

# Snapshot
zfs snapshot data/shared@$(date +%Y-%m-%d)
zfs list -t snapshot

# Replace failed drive
zpool replace data /dev/disk/by-id/OLD_ID /dev/disk/by-id/NEW_ID

Troubleshooting

ZFS pool degraded

zpool status data
# Replace failed drive – see ZFS Management section above

Samba share not accessible

systemctl status smbd nmbd
testparm -s
zfs list data/shared && ls -la /raid5/shared

Jenkins job failed

cat /var/lib/jenkins/jobs/Backup-CVJM/builds/lastFailedBuild/log
systemctl restart jenkins

ZFS pool not mounted after reboot

zpool import data
systemctl status zfs-import-cache zfs-mount
